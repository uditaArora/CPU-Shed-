FCFS

First Come First Serve

The simplest scheduling algorithm. Processes are executed in the exact order they arrive in the ready queue. No priority, no preemption — whoever came first gets the CPU first.

PreemptionNone
ComplexityO(n log n)
StarvationNo
OverheadVery Low

Performance

Time ComplexityO(n log n)
Space ComplexityO(n)
Avg WT (worst)High

SJF

Shortest Job First

At each scheduling decision point, the process with the shortest CPU burst time is selected. This is provably optimal for minimizing average waiting time, but requires knowing burst times in advance.

PreemptionNone
ComplexityO(n²)
StarvationYes
Optimal WTYes

Performance

Time ComplexityO(n²)
Space ComplexityO(n)
Avg WTMinimum

✅ Pros

✓

✓

❌ Cons

✗

✗
Burst time must be known
✗
Not practical in real OS

Round Robin

Round Robin

Each process gets a fixed time slice (quantum). When a process's quantum expires, it's preempted and added to the back of the ready queue. Excellent for time-sharing systems.

PreemptionYes
ComplexityO(n)
StarvationNo
QuantumConfigurable

Performance

Time ComplexityO(n·q)
Space ComplexityO(n)
Response TimeLow

✅ Pros

✓
Fair — no starvation
✓
Good response time

❌ Cons

✗
High context-switch overhead
✗
Quantum size is critical

Priority

Priority Scheduling

Each process is assigned a priority number. The scheduler always selects the highest priority (lowest number) process from the ready queue. Ties are broken by arrival time.
